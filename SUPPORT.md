# Beacon Support Policy

Beacon is currently a pilot-stage proprietary product.

## Supported usage

- the latest immutable release;
- documented CLI and reusable-action workflows;
- bundled readiness packs and versioned public schemas;
- local, read-only execution against explicitly configured evidence.

Preview and experimental features may change within the `0.x` release series.
Schema compatibility follows the rules documented with each public contract.

## Requesting help

Use a repository issue for reproducible product defects and feature requests.
Include the Beacon version, operating system, command, sanitized configuration,
expected result, and actual result. Never attach secrets or raw production data.

Security concerns must follow `SECURITY.md`, not the public issue tracker.

## Response expectations

Support is best-effort during the pilot. Service teams remain responsible for
release approval, incident response, infrastructure changes, and validation of
Beacon recommendations in their environment.
